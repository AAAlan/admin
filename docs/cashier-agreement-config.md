# 收银台协议配置说明

## 1. 功能概述

协议设置用于配置收银台中“隐私协议”和“用户协议”的跳转地址。配置按语言分别维护，收银台根据当前语言优先使用对应语言的链接；对应语言没有配置时，按区域使用缺省语言链接。

当前页面是一个统一的收银台配置，不按游戏、国家、币种或支付环境拆分协议配置。页面不展示收银台预览，提供协议链接编辑、保存和整体发布操作。

入口：海外支付中心 > 协议设置，路由为 `/agreement/links`。

## 2. 支持语言

| 顺序 | 语言 | 语言代码 | Locale | 海外回落语言 |
| --- | --- | --- | --- | --- |
| 1 | 简体中文 | `zh_CN` | `zh-CN` | 否 |
| 2 | English | `en` | `en-US` | 是 |
| 3 | 繁體中文 | `zh_TW` | `zh-TW` | 否 |
| 4 | 日本語 | `ja` | `ja-JP` | 否 |
| 5 | 한국어 | `ko` | `ko-KR` | 否 |
| 6 | 德语 | `de` | `de-DE` | 否 |
| 7 | 法语 | `fr` | `fr-FR` | 否 |
| 8 | 俄语 | `ru` | `ru-RU` | 否 |
| 9 | 泰语 | `th` | `th-TH` | 否 |
| 10 | 西班牙语 | `es` | `es-ES` | 否 |
| 11 | 巴葡 | `pt_BR` | `pt-BR` | 否 |
| 12 | 印尼 | `id_ID` | `id-ID` | 否 |

协议语言集合独立于通用的多语言文案配置，不会改变其他多语言配置页面的语言数量。

## 3. 页面功能

### 3.1 语言列表

- 左侧展示 12 种语言及其 Locale。
- 点击语言后，右侧切换到该语言的协议编辑表单。
- 绿色状态点表示该语言的隐私协议和用户协议均已填写；灰色状态点表示至少有一个链接为空。
- 当前语言高亮显示。

### 3.2 协议链接

每种语言有两个独立字段：

- 隐私协议链接：用户点击“隐私政策”时打开。
- 用户协议链接：用户点击“用户协议”时打开。

两个字段分别校验、分别保存。只填写其中一种协议时，不会因为另一种协议为空而阻止保存，但已填写的协议必须满足该协议自己的回落规则。

### 3.3 保存草稿

- 保存草稿和发布操作位于页面顶部标题区右侧。
- 页面内容与最近一次保存结果不一致时，显示“有未保存的更改”。
- 点击“保存草稿”时会校验全部 12 种语言的字段，而不只是当前正在查看的语言。
- 保存成功后更新保存时间、重置未保存状态，并显示“协议设置已保存”。
- 没有填写任何协议链接时也可以保存，表示当前不下发协议入口。

### 3.4 整体发布

- 保存和发布是两个独立动作：保存只生成或更新协议配置草稿，发布才会改变收银台当前生效版本。
- 点击“整体发布”会一次性发布当前已保存的 12 种语言、两类协议链接，不按当前选中语言拆分发布。
- 发布按钮仅在没有未保存修改且存在未发布变更时可用。
- 发布前会再次执行全部语言的 URL 和缺省语言校验，避免绕过保存校验发布无效配置。
- 点击发布后需要二次确认；确认后立即生效，并记录发布时间。
- 页面顶部会分别显示保存状态和发布状态：未发布变更、尚未发布或最近一次发布时间。
- 如果只修改了部分语言，仍以整个 12 语言配置快照发布，未修改语言会保持原已保存内容。

## 4. 校验规则

### 4.1 URL 格式

协议链接为空时视为未配置，不报错。非空值必须是完整的绝对 URL，并且协议只能是：

- `http://`
- `https://`

以下内容会校验失败：

- `example.com/terms` 等相对地址或缺少协议的地址
- `mailto:`、`javascript:`、`ftp:` 等其他协议
- 无法被标准 URL 解析的字符串

输入框失焦后会显示字段级错误；点击保存时会重新校验全部语言，并在页面上标记所有不合法字段。存在不合法链接时，保存被阻止，并提示“存在格式不正确的链接，请检查后再保存”。

### 4.2 缺省语言回落

回落按“协议类型”分别计算：

1. 如果当前语言有链接，使用当前语言链接。
2. 如果当前语言为空，使用区域缺省语言链接。
3. 当前语言和缺省语言都为空时，该协议没有可用链接，收银台不展示该协议入口。

海外区域的缺省语言为 English。国内区域的缺省语言为简体中文。

只要某种协议在任意语言填写了链接，就必须填写该区域的缺省语言链接。例如，海外只填写日语隐私协议而没有填写 English 隐私协议时，保存会被阻止；用户协议是否填写不影响隐私协议的判断。

### 4.3 文本处理

- 保存和读取时会去除链接首尾空格。
- 空格字符串等同于空值。
- 不检查链接是否可访问、是否返回 2xx、是否指向隐私协议页面，也不检查不同语言链接是否重复。

## 5. 特殊场景

| 场景 | 系统行为 |
| --- | --- |
| 只配置 English | 其他 11 种语言回落到 English，可保存 |
| 只配置某个非 English 语言 | 海外缺少 English 回落链接，保存失败 |
| 只配置隐私协议 | 隐私协议按规则生效，用户协议保持未配置 |
| 只配置用户协议 | 用户协议按规则生效，隐私协议保持未配置 |
| 12 种语言全部为空 | 可保存，两个协议入口均不展示 |
| 当前语言字段为空但 English 有值 | 当前语言使用 English 链接 |
| URL 首尾有空格 | 保存时自动去除首尾空格后存储 |
| 当前页面有未保存修改后切换语言 | 修改保留在当前表单中，直到保存或刷新页面 |
| 保存过程中重复点击保存 | 保存按钮在保存状态下禁用 |
| 保存后未发布 | 收银台继续使用最近一次已发布版本，页面显示“有未发布的更改” |
| 只修改部分语言后整体发布 | 12 种语言作为一个整体快照发布，其他语言沿用已保存内容 |
| 发布前仍存在非法链接或缺少 English 回落 | 发布被阻止，需要先修正配置 |
| 将已发布链接全部清空并保存 | 生成清空协议的待发布版本；整体发布后两个协议入口均不展示 |
| 发布确认时关闭或取消 | 不改变已发布版本，待发布状态保持不变 |
| 浏览器无法写入 localStorage | 当前 Mock 实现会忽略写入异常；页面仍可能显示保存成功，生产环境应改为后端接口并返回明确错误 |
| 清理浏览器站点数据 | 本地保存的协议配置会被清除 |

## 6. 数据结构与存储

当前项目为 Mock 实现，使用浏览器 `localStorage` 保存配置。正式接入后端时，应保持相同的字段语义并由服务端负责权限、版本和发布控制。

### 6.1 存储键

- 海外：`cashier_agreement_links_overseas_v1`
- 国内：`cashier_agreement_links_domestic_v1`

两个区域的配置相互隔离。每个存储键的值是以配置主体标识为 key 的对象，统一收银台配置使用固定标识 `__global_cashier__`。

### 6.2 条目结构

```json
{
  "appId": "__global_cashier__",
  "privacy": {
    "zh_CN": "https://example.com/privacy",
    "en": "https://example.com/en/privacy",
    "zh_TW": "",
    "ja": "",
    "ko": "",
    "de": "",
    "fr": "",
    "ru": "",
    "th": "",
    "es": "",
    "pt_BR": "",
    "id_ID": ""
  },
  "user": {
    "zh_CN": "https://example.com/terms",
    "en": "https://example.com/en/terms",
    "zh_TW": "",
    "ja": "",
    "ko": "",
    "de": "",
    "fr": "",
    "ru": "",
    "th": "",
    "es": "",
    "pt_BR": "",
    "id_ID": ""
  },
  "updatedAt": "2026-09-28T08:00:00.000Z",
  "publishedAt": "2026-09-28T08:10:00.000Z"
}
```

读取配置时会补齐缺少的语言字段，因此从旧版本只有 5 种语言的配置升级到当前版本时，原有链接保留，新增 7 种语言默认为空。

草稿和已发布版本分开保存。海外已发布版本使用存储键 `cashier_agreement_links_published_overseas_v1`，国内已发布版本使用 `cashier_agreement_links_published_domestic_v1`。整体发布时会将当前统一收银台草稿复制为已发布版本，并写入新的 `publishedAt`。
